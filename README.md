# 用户隐私权利请求履约工作台

覆盖访问、更正、删除、撤回同意和限制处理请求的多页面履约工作台。项目使用 Next.js App Router、Chakra UI、Zustand、TanStack Query、tRPC、Zod 和 TypeScript 构建。

## 功能

- 客服登记请求，根据地区、身份核验状态和请求类型生成处理步骤与期限。
- 定位相关系统、分派任务、登记执行证据、合并跨系统结果并记录处理意见。
- 身份材料只保存掩码引用和摘要，不保存材料明文。
- 重复请求、身份材料不足、跨系统结果冲突自动进入复核队列。
- 支持任务开始、完成和阻断，冲突逐项复核，延期必须填写原因。
- 截止时间前关闭必须记录提前关闭理由，未完成任务或存在冲突时服务端拒绝关闭。
- 汇总登记、核验、分派、证据、冲突、延期和关闭审计，导出脱敏处理包。

## 系统清单版本与发布重算

系统退役、维护或支持范围变化不会直接改动在途请求，而是走「待生效版本 → 发布对账批次」流程（见「系统清单」页）：

- **待生效版本**：管理员编辑清单（系统增删、状态、支持请求类型、SLA）后提交，先进入待生效版本，不立即影响有效清单。
- **并发只放行一位**：两个管理员基于同一有效版本提交时，先到者进入待生效；后到者保留为**冲突草稿**并可查看与抢先版本的差异，同一管理员重复提交则修订原待生效版本。
- **发布对账**：发布时为受影响请求建立对账批次——冻结发布时点之前的证据（`frozenAt` / `frozenByVersionId`，原始回执继续可查），按新版本重算任务：只补生成缺失任务，已完成任务原样保留；退役或不再支持该请求类型的系统，其未完成任务自动转阻断。已完成/已拒绝请求只冻结回执并标记跳过，不重算。
- **检查点续跑**：批次逐项处理并持久化 `nextIndex`；发布中途失败保留检查点，重试只补未完成项。任务去重按稳定步骤 ID，审计使用稳定条目 ID，续跑不会重复任务或审计。可勾选「模拟发布中断」演示。
- **有效版本一致性**：只有批次全部成功后新版本才成为有效版本并切换 `systems`；总览、请求详情、系统清单和导出包统一按当前有效版本呈现。
- **旧数据回填**：缺少版本信息的历史 `localStorage` 数据会先回填出 `inv-v1` 有效版本、给请求和任务补盖版本戳，再参与重算。

tRPC 路由使用 Zod 校验操作输入；TanStack Query 管理服务数据；Zustand 管理工作区筛选状态；每次成功操作都会把完整工作区写入浏览器 `localStorage`。

## 运行

```bash
npm install
npm run dev
```

开发服务地址：`http://localhost:18457`

## 构建与验证

```bash
npm run build
npm run start
npm run verify   # 版本发布/检查点续跑/并发/回填的端到端逻辑验证（tsx）
```

## 目录

```text
src/
  app/          Next App Router 页面与 tRPC API Handler
  components/   应用外壳、页面头、状态标签
  features/     总览、请求列表、请求详情、复核、系统、审计
  lib/          Zod Schema、tRPC 客户端、TanStack Query Hooks、本地存储
  server/       tRPC 服务路由
  services/     流程模板和履约业务规则
  stores/       Zustand 工作区状态
  types/        领域类型
```
